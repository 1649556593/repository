# C++ 学习笔记整理工作流

> 用途：以后整理 `text*.cpp` 这类学习笔记时，按这个标准执行。  
> 目标：生成一份结构清晰、内容完整、适合复习的 `.md` 笔记，而不是对原笔记做评论。

## 1. 整理范围

先确认本次只整理哪个源文件。

规则：

- 用户指定 `text3.cpp`，就只整理 `text3.cpp`。
- 不把不同日期、不同文件的内容混在一起。
- 新生成单独的 `.md` 文件，不覆盖之前的整理版。
- 原 `.cpp` 文件默认不修改，除非用户明确要求改代码。

文件命名建议：

```text
STL.md
文件读写+模板.md
text4学习笔记整理.md
```

## 2. 整理原则

整理后的笔记必须是“学习笔记”，不是“批改意见”。

不要写：

```text
你原注释写到……
这句应该保留……
上一版……
我认为……
你这里理解得对……
```

应该写成中性的笔记正文：

```text
for_each 的底层逻辑可以理解为 func(*it)。
set 的比较规则不仅决定排序，也决定元素是否等价。
```

写错的地方直接修正为正确版本，不在正文里反复评价。

## 3. 注释处理规则

源文件中的注释分三类处理。

### 3.1 API 型注释

例如：

```cpp
// push_back(elem); // 尾部插入元素
// pop_back();      // 删除最后一个元素
```

整理方式：

- 放在对应知识点小节下。
- 可以整理成表格或代码块。
- 不遗漏函数名、参数含义和用途。

### 3.2 推导型注释

例如：

```cpp
// myprint的参数就是这一层vector里存储的参数类型，底层是func（*it）
```

整理方式：

- 必须保留其逻辑。
- 不能压缩成一句结论。
- 放回对应知识点的位置。
- 用更清晰的语言展开推导过程。

示例整理：

```text
for_each(v.begin(), v.end(), myprint) 的底层逻辑可以理解为：

for (auto it = v.begin(); it != v.end(); ++it)
{
    myprint(*it);
}

所以函数参数类型取决于 *it 的类型。
```

### 3.3 个人理解型注释

例如：

```cpp
// 本质上只要编译器看到_M_comp(a,b)这行代码是合法可调用的，模板就能顺利编译通过
```

整理方式：

- 必须保留理解路线。
- 不放到最后统一总结。
- 放在对应章节中，例如这句应放在 `set` 排序规则、仿函数、函数指针小节。
- 可以修正不精确的说法，但不要删掉思考过程。

## 4. 注释放置规则

注释原来属于哪个知识点，整理后就放在哪个知识点下面。

示例：

| 原注释内容 | 整理后位置 |
| --- | --- |
| `vector` 动态扩展、`capacity`、`reserve` | `vector` 容器详解 |
| `for_each` 底层是 `func(*it)` | `vector` 遍历或容器嵌套 |
| `list` 不支持随机访问，不能用标准 `sort` | `list` 反转和排序 |
| `set` 底层比较器、仿函数、函数指针 | `set` 排序规则 |
| 自定义类型必须指定排序规则 | `set` 存放自定义类型 |

禁止把重要推导注释集中放到最后。

## 5. 错误修正规则

如果源笔记中有明显错误，整理时直接改成正确写法。

示例：

```cpp
vector<int> v3(10, 100);
vector<int> v3(v2);
```

整理为：

```cpp
vector<int> v3(10, 100);
vector<int> v4(v2);
```

再例如：

```text
find 没找到返回 -1
```

整理为：

```text
find 没找到返回 string::npos。
```

不需要写“这里写错了”，除非这个错误本身很容易踩坑，可以在对应章节用中性方式说明。

## 6. 内容补充规则

可以补充内容，但要克制。

适合补充：

- 代码缺少必要头文件。
- 某个函数的返回值或边界条件没写清楚。
- 某个概念影响后续理解，例如迭代器类型影响能否使用 `sort`。
- 学习内容明显不完整，例如文件读写、模板、STL 容器的关键缺口。

不适合补充：

- 超出当前学习阶段太多的现代写法。
- 大量没学到的容器或高级机制。
- 把笔记改成百科全书。

补充内容要放在对应知识点下，不单独堆在最后。

## 7. 章节结构规则

章节按学习顺序组织。

推荐结构：

```text
1. 总览
2. 基础概念
3. 第一个容器/主题
4. 构造
5. 赋值
6. 大小
7. 插入删除
8. 数据存取
9. 排序或特殊操作
10. 案例
11. 容器/知识点选择速查
```

每个章节内部顺序：

```text
概念
常用接口
示例代码
底层理解或推导
注意点
```

## 8. 代码整理规则

代码示例应做到：

- 能单独阅读。
- 命名统一。
- 缩进整齐。
- 明显笔误要修正。
- 不保留大量重复 `main()`，除非用于区分独立示例。
- 必要头文件写清楚。

代码中的注释保留为学习注释，不写评价语气。

示例：

```cpp
sort(d.begin(), d.end()); // 默认从小到大
```

## 9. 语气规则

使用笔记语气。

保留：

```text
本质是……
可以理解为……
底层逻辑是……
注意……
区别……
规则……
```

避免：

```text
你这里……
你原来……
我觉得……
这个锅我接……
这句很棒……
```

## 10. 最终检查清单

生成 `.md` 后检查：

- 是否只整理了用户指定的源文件。
- 是否生成独立 `.md`，没有覆盖旧笔记。
- 是否没有把重要注释堆到最后。
- 是否没有评论式语言。
- 源文件中的推导型注释是否保留并放在对应章节。
- 明显错误是否已经直接修正。
- 补充内容是否克制并贴合当前学习阶段。
- 目录和标题是否清晰。
- 代码块是否完整、缩进是否整齐。
