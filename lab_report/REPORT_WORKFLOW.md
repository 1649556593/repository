# 解题报告工作流

## 1. 用途

这份文档用于固定“洛谷数据结构/算法题解题报告”的生成规则，方便后续继续批量让 Codex 按同一格式补写。

当前这一套规则，是根据现有 `lab_report1.md` 到 `lab_report10.md` 整理出的最终版本。

---

## 2. 固定规则

### 2.1 文件组织

1. 每个 Markdown 文档写 `4` 道题。
2. 文件命名按顺序递增：
   - `lab_report1.md`
   - `lab_report2.md`
   - `lab_report3.md`
   - ...
3. 当前已经做到 `lab_report10.md`。
4. 下次继续时，新文件应从 `lab_report11.md` 开始。

### 2.2 旧文件处理规则

1. 默认不修改已经完成的旧报告。
2. 只有在我明确要求“统一修改”时，才批量调整旧文件。
3. 新任务优先继续往后新建，不回头重写旧文档。

### 2.3 总览表规则

总览表必须保留：

1. 题号
2. 核心题名
3. 难度
4. 知识点

总览题目名称格式：

- `P1030 求先序排列`
- `P5318 查找文献`
- `B3616 队列`

说明：

1. 保留题号，如 `Pxxxx`、`Bxxxx`。
2. 去掉比赛/标签前缀，如：
   - `[NOIP 2011 普及组]`
   - `【模板】`
   - `【深基...】`
   - `[信息与未来 2021]`
3. 只保留题号 + 核心题名。

### 2.4 正文标题规则

每道题必须用实际题名作一级标题，不能写成统一的“题目名称”。

正确示例：

- `# （一）后缀表达式`
- `# （二）表达式括号匹配`
- `# （三）括号序列`

错误示例：

- `# （一）题目名称`

### 2.5 图片和代码规则

当前默认规则：

1. 不补图片。
2. 不补真实代码。
3. 保留 `代码实现` 小节。
4. 代码块统一写成：

```c
Talk is weak，show your code plz.
```

如果以后我单独说明“要补图片”或“要补代码”，再按新要求处理。

## 4. Codex 执行流程

以后让 Codex 继续补报告时，按下面流程执行：

1. 读取现有 `lab_report` 目录，确认最新文件编号。
2. 识别我这次给出的题号或截图中的题号。
3. 排除已经做过的重复题目。
4. 按我给出的顺序分组，每 `4` 题一个 `.md`。
5. 去洛谷抓题面要点：
   - 题意
   - 数据范围
   - 时间/空间限制
   - 适合的知识点
6. 生成新报告文件。
7. 只写分析，不补图片和真实代码。
8. 检查：
   - 总览是否保留题号
   - 总览是否去掉比赛前缀
   - 一级标题是否和题目一一对应
   - 每份是否正好 `4` 题

## 5. 后续直接可复制的话术

以后如果继续做新一批题，可以直接发：

```text
继续按 lab_report 的既有格式做解题报告。
规则不变：
1. 一个文档 4 道题；
2. 总览题目名称保留题号，如 P1030 求先序排列；
3. 去掉比赛前缀，只保留题号 + 核心题名；
4. 正文一级标题写实际题名；
5. 图片和真实代码都先不做，代码实现保留占位代码块；
6. 不改旧文件，只新建后续编号文件。

这次题目是：
Pxxxx
Pxxxx
Pxxxx
Pxxxx
...
```

如果是截图形式，可以直接发：

```text
继续按 REPORT_WORKFLOW.md 的规则处理这批题，还是 4 题一个文档，不改旧文件。
```
